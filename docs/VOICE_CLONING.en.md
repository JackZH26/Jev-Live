# One English reference voice across languages

> **Paused (2026-09-21):** Listening review led to restoring the original Melo English female voice. All commentary and replies now use English; the five UI languages remain. The material below is an experiment archive. The desktop clone controls are removed and saved experimental settings migrate to English Melo. The old clone UI smoke script does not apply to this release.


[简体中文](VOICE_CLONING.md)

In Character & Hosting, select **English voice clone · one multilingual voice**, import an English WAV and enter its exact transcript. Commentary and Chinese, English, Japanese and Korean replies reuse that voice. Simplified and Traditional Chinese remain separate text options but both use the model's Chinese language; a Taiwanese accent is not implied.

Use 3–20 seconds of clear speech from one speaker, without background music: 16-bit PCM WAV, 16–48 kHz, mono or stereo, at most 4 MB. An existing English female voice recording can be used. The application copies it to its private `voice-references/` directory, outside public overlay assets. Audio stays local and outside Git. The transcript must match the recording; importing a replacement clears the previous transcript.

Cloning requires Qwen3-TTS **0.6B Base**, not the existing **CustomVoice** preset model. The first utterance builds a reference prompt; every language reuses it until the audio or transcript changes. Speaker identity is conditioned consistently, while pronunciation, prosody and perceived similarity require listening. Selected Qwen presets also remain selected when replying in another language.

## Install and run

Adjust paths for your PC:

```powershell
.\scripts\install-local-voice.ps1 -RuntimeDirectory E:\JevRuntime -CloneVoice
.\scripts\start-clone-voice.ps1 -RuntimeDirectory E:\JevRuntime
```

Add `-CPU` to both commands for CPU execution. Installation downloads public dependencies and pinned weights; inference runs offline. The default GPU allocation cap is 3072 MiB; CUDA, Steam and OBS need additional headroom. Benchmark CPU performance before using it live; model loading alone is insufficient.

Pinned model: `Qwen/Qwen3-TTS-12Hz-0.6B-Base`, revision `5d83992436eae1d760afd27aff78a71d676296fc`. The service listens on `127.0.0.1:11438`, separately from Melo and preset Qwen. Inference has a 25-second deadline and the desktop a 35-second timeout. Failure keeps captions and reports an error without substituting another speaker. Preflight checks the reference and service identity; previews establish actual waiting time.

Five preview buttons test each language without changing the default host language or starting a broadcast. Stop automatic hosting before importing, changing or previewing voices.

## Validation

```powershell
npm run check
npm test
E:\JevRuntime\tts-env\Scripts\python.exe -m unittest discover -s services -p 'test_voice*.py'
node scripts/smoke-voice-clone.cjs --reference=english.wav --transcript=english.txt
```

The final command uses a fake speech service to test the real desktop, import, routing and local playback. It does not certify model quality. Add `--real` with the clone service running for real desktop synthesis. The script uses an isolated profile, without existing platform accounts or broadcasts.

For real model timing and saved WAV files:

```powershell
node scripts/benchmark-voice-clone.cjs --reference=english.wav --transcript=english.txt --out=test-results/voice-clone
```

Evaluation may use `services/local_voice.py --deadline 180` to let slow samples finish. This is an evaluation setting; the desktop still enforces 35 seconds. Reports record synthesis time, audio duration, prompt reuse and whether results meet the production service's 25-second limit. Distinguish a technical test voice from the user's selected target voice.

### Local measurements (2026-09-21)

200 TypeScript tests, five Python tests, type checks and the build passed. The real Electron UI used a fake speech service to verify import, persistence, five-language labels and all preview buttons. Its fake latency is not model performance.

Real Qwen Base inference on CPU (eight threads), using a 6.24-second reference generated by the existing Melo English voice:

| Language | Synthesis wait | Audio duration | Reference prompt reused |
| --- | --- | --- | --- |
| English | 30.76 s | 3.04 s | Created initially |
| Simplified Chinese | 22.17 s | 2.32 s | Yes |
| Traditional Chinese | 25.39 s | 2.80 s | Yes |
| Japanese | 26.00 s | 2.80 s | Yes |
| Korean | 21.61 s | 2.40 s | Yes |

These samples establish multilingual inference and prompt reuse, **not acceptable live-host latency**. Three exceed the default 25-second service deadline. An evaluation-only 180-second limit allowed completion; production limits remain unchanged. This test voice is not Astesi. Human listening and speaker-similarity acceptance are not claimed. Other applications occupied most VRAM, so GPU inference was not started and the running host configuration was not switched.

## Astesi candidate inspection (2026-09-21)

The supplied [hatsuyuki/so-vits-svc-41-astesi](https://huggingface.co/hatsuyuki/so-vits-svc-41-astesi/tree/main) repository is at revision `ef74e21ac2ce07068c55e9c936dc800c92c21535`. It contains `G_600000.pth`, `config.json`, optional diffusion weights, clustering data and a converted song FLAC. Its 44.1 kHz, `vec768l12`, single-speaker `astesi: 0` configuration matches the so-vits-svc 4.1 conversion architecture.

This is an audio conversion model. Its weights cannot be imported as Qwen weights or a reference WAV. The repository has no English speech reference, model card or declared voice-model license. Its song sample does not establish English or multilingual conversational quality. Inspection covers files, configuration and interface compatibility only; Astesi inference has not been run, selected by default or bundled.

A candidate workflow is English speech → so-vits-svc Astesi conversion → listening review and clean English reference → this multilingual cloning feature. It still needs the corresponding ContentVec encoder, pitch extraction and a real conversion test. An extra conversion can degrade quality. Per-utterance TTS followed by conversion is another candidate requiring separate runtime integration and latency measurements.
