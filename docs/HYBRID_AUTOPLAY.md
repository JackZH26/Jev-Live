# Jev 战术决策 + 共用 Bot 执行器

[English](HYBRID_AUTOPLAY.en.md) · 作者：[JackZH26 / X](https://x.com/jackzhj)，欢迎关注交流。

## 目标与现有证据

2026-09-20 云端实测证明 Jev 的决策响应中位数约 360 ms、P95 约 435 ms；另一轮 106 个游戏位置采样完全相同。目标已传给游戏，却没有产生位移。继续提高模型调用频率无法解决这一执行问题。详见[原始验收结论](CLOUD_JEV_VALIDATION.md)。

本次调整让 Steam Playtest 的自动玩家与现有 Bot 共用寻路、武器、环境危险应对和脱困代码，Jev 决定下一步去哪里、是否交战、撤退和跨房间方向。必须保留玩家控制器，否则相机、HUD、背包、玩家状态和手动接管会受影响。

## 三层职责

| 层 | 职责 | 节奏 |
| --- | --- | --- |
| Jev 战术层 | 从游戏提供的可行动目标中选择交战、掩护、搜刮、探索、转移；使用近期路线、失败记录和自身资源 | 事件触发，至少间隔 800 ms；单个在途请求；1.2 s 超时 |
| 本地调度层 | 验证目标、紧急撤离、危险情况下治疗/换弹/换枪优先级、目标稳定性、失败冷却、云端失联回退 | 每个新鲜游戏观测，约 20 Hz |
| 共用执行层 | `UEtcBotBrainComponent` / `UEtcBotAimComponent`；UE 路径跟随、碰撞移动、射击和技能、交互、危险应对、无位移恢复 | Brain 20 Hz；UE 路径跟随和瞄准随引擎帧执行 |

保留原 Bot 的战略入口；自动玩家使用同一个 Brain 的外部目标入口。玩家仍由 PlayerController 持有，配上 UE 的 PathFollowingComponent。现有 AIController 继续走原生 MoveToLocation。两者复用 Brain 的执行代码，而非并行维护两套移动实现。

## 目标与交接契约

* 只允许本次观测列出的行动 ID；云端不能提供自由坐标、任意函数或控制台命令。
* `session / matchId / epoch / frame` 限定所有权，拒绝旧对局、旧模式、旧观测结果。
* 战术目标软有效期 4 秒；本机仍需持续发送 250 ms 控制租约。云端超时由本地策略接替，本机控制进程失联必须释放所有输入。
* 同一个目标只续期，不清空路径、反复松按射击或重置无位移计时。目标实质变化才切换任务。
* 状态包括执行中、已完成、受阻、暂停和已释放，并提供目标 ID、原因、路径状态及失败计数。旧目标的反馈不能误伤新目标。
* 优先级：手动接管/失焦/租约失效 > 引擎危险应对 > 即时生存动作 > Jev 战术目标 > 本地常规策略。
* 目标完成、受阻、房间变化、敌情变化、危险变化触发重新思考；失败目标短期冷却。云端响应到达前，执行器继续当前有效目标。
* 扫描采用现有 Bot 的掩体观察和短距离探索，避免长期站在原地转镜头。

## 公平性与适用范围

不修改生命、伤害、弹药、速度、碰撞或传送条件。瞄准参数以现有 Pro Bot 为起点；玩家武器按真实相机射线校准。仅传玩家当前可见/公开标记信息，不使用隐藏敌人、未公开的下一轮危险区或最终安全房间。现有 Bot 内部有未来安全区规划逻辑；外部目标入口必须绕开这一战略分支。

该原生接入首先用于 ETC 离线 Steam Playtest。任意 Steam 游戏需要各自的原生适配或视觉/输入适配，不能宣称通用游戏都能复用 ETC AIController。

## 实施与发布

1. 在 Studio 中加入带有效期的战术目标、事件触发、失败反馈和能力协商；旧 v3 游戏保持原行为。
2. 在 EtcCore 模块复用 Bot Brain、Aim 和 UE 路径跟随；桥接只负责观测、验证、交付目标和反馈。
3. 原生修改保存成可审查补丁及安装流程；不改 Lyra 引擎/基础模块。
4. 执行类型检查、策略测试、原生编译和自动化测试；通过后再打包 Steam 候选构建并安装验证。
5. 验收必须使用实际 Steam Playtest，可视画面、位移、射击耗弹、过门和比赛结算分别举证。编辑器运行不能替代。

## 分阶段验收门槛

| 阶段 | 验收要求 |
| --- | --- |
| 协议与安全 | 拒绝旧 epoch/对局/观测；目标续期不重启路径；反馈与目标对应；云端超时回退；手动接管和输入释放 |
| 基础操控 | 覆盖房间 005、031、门口、箱子、平台边缘等至少 40 条路线；不能无故静止超过 3 秒而没有受阻/恢复反馈 |
| 完整比赛 | 至少 20 场，进入比赛、拿装备、战斗、转移、结算和再开闭环；记录中断，不把中断算作完成 |
| 分档对战 | 相同地图种子、装备和公开信息条件，对 Easy/Regular/Advanced/Expert/Pro 分档；100 场先估计，必要时扩充到 400 场；对 Pro 胜率的 95% 置信下界须超过 50% |
| 多人混战 | 19 个 Pro 对手；与相同执行器、关闭 Jev 的基线配对比较，报告胜率、名次、生存时间、击杀、房间覆盖、卡住率及延迟 |
| 长期直播 | 完成两小时完整直播，再做 8/24/72 小时；游戏能力和直播稳定性分开记录 |

“超过当前所有 BOT”是项目目标，不是当前结论。只有分档对战与混战统计达标，才能在相应测试条件下作出超过现有 Bot 的结论；不声称超过其他游戏或全球所有 Bot。
