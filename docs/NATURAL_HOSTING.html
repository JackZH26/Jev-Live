更像玩家的自动主持：可落地改进方案

English · 手机阅读版

日期：2026-09-21。审查基线：61f60e1。作者：JackZH26 · 𝕏 @jackzhj。

本文件是设计方案，尚未实现或通过实时验收。 依据当前源码、本机保存的非敏感配置和既有实测记录；没有本次试看录像的逐帧计时，不能把推断当成该场直播的精确归因。

本轮追加交付：模拟评论与多语言语音回复。该测试入口和语言路由已实现，其余架构改造仍按本方案推进。用户指定直播默认英语；支持的评论语种用对应语言回复，其他语种回退英语。

1. 建议与预期体验

把主持改成“持续了解局势、挑值得说的事、即时短反应、自然表达行动、空闲时聊准备好的话题”的系统。继续使用现有 ETC/JEV、Ollama、MeloTTS 和 OBS，先解决信息与调度，再评估语音升级。

主播应该有贯穿一局的关注点。例如“先找主武器”之后，看到箱子想去搜；遇到敌人会改口；拿到武器后记得兑现；失败时能针对刚才的冒险自嘲。像玩家的关键是注意力、行动、话语和情绪连续，随机性只影响表达方式。

本轮优先 ETC Steam 实机。自动玩时表达已经采纳的行动意图；手动玩时表达观察和建议，不虚构自己正在控制。两种模式都持续主持，主持故障不能阻塞游戏控制。保留 AI 身份说明，同时追求自然的直播表现。

本机保存配置为 Qwen3.5-4B / CPU + MeloTTS。2026-09-20 的 CPU 热请求完整文本中位数为 5.45 秒；Melo 简中短句为 1.34 秒。这两批样本不是同一次端到端测试，但串行实现足以解释“数秒后才开口”的风险。GPU 文本样本中位数 0.46 秒，负载并不完全一致，不能直接当成实战承诺。见文本模型实测与语音实测。

还要区分两种延迟：游戏事件到本机 OBS 出声，及 OBS 到观众播放器。观众端若画面和语音一起晚到，是传输延迟；若语音描述已过去的画面，是内容陈旧或音画相对偏移。当前 responseP95Ms 只到生成/发布附近，不包含真实播放和观众端；不能据此宣布问题解决。

3. 先把“知道什么”接完整

增加只读 HostWorldState，从现有 ETC 观察、已采纳目标与执行器反馈构造，保留每项信息的采集时间、来源和局内身份。通过前后快照差异产生事件，而不是每次控制心跳都说一句。

首批事件：受伤、血量危险、可见敌人出现、弹匣耗尽、可搜物出现、目标改变、武器变化、进入房间、危险/撤离阈值、目标受阻、死亡和明确结算。连续伤害合并、重复目标续租去重；关键危险立即处理，菜单抖动才做稳定判定。

信息可信顺序：玩家可见的游戏结构化反馈 → 有效且已采纳的行动/执行反馈 → 带时间的 OCR → 可选截图理解 → 外部游戏资料。外部攻略不能证明本局箱子里有什么；未在玩家视野或已公开地图内的信息不能成为主播的“发现”。当前接口没有可靠屏幕左右方向时，只说“有人”，不凭世界坐标编出“左边有人”。

ETC 已有结构化接口，无需把连续多模态识图放在紧急反应路径。截图理解可按新房间、未知物件等触发，作为低优先级补充；保留截图拍摄时间，晚到结果不得覆盖新状态。其他游戏没有接口时，另行验收 OCR/视觉路径的准确性和延迟。

JEV 当前 systemOne 请求只取 action 与 destination，没有可直接播的完整思考。记录 proposed → accepted → issued → running → succeeded/blocked/cancelled 的事实链，包含 source=jev/local/manual。云端提议被本地规则拒绝，或只是备选撤离目的地，都不能说成“我们现在过去”。

可选的 reasonCode 是简短、可核验的行动依据，例如低血量、缺少主武器、房间即将危险。优先从真实状态/执行反馈派生，不追加一次长推理拖慢控制，也不虚构 JEV 的内部推理过程。

具体武器名、数量、结果和位置必须来自允许的事实槽位，并绑定事件/资料证据；模型擅自新增的具体事实应重写或取消。自由口语围绕这些槽位生成，不能把“提示模型别编造”当作事实校验。本轮模拟评论里仍出现了无依据的 AR-15 说法，证明这一层需要成为实施门槛。

4. 三类内容，共用一个说话调度器

三类是代码职责，不要求部署三个大模型。所有类别共用一条音频播放通道和同一人设。

内容来源与生成方式建议初始行为
即时短反应确认事件触发，选择同音色预合成短句0.4–2 秒音频，如“有人！”“先撤！”；仅在事实匹配时播放，事件发生到本机首声 P95 目标 ≤1 秒
行动和局势表达已采纳行动、当前事实和短期记忆，经本地模型生成一到两个短分句，通常 2–6 秒；动态内容首声 P95 目标 ≤2.5 秒，属于优化目标，当前 CPU 路径尚未证明可达
等待、互动和小话题本局回顾、观众消息、预取素材卡每段 6–15 秒，在句间留空；危险或开局可打断，不让搜索占住话筒

即时库第一版可以做 8–12 类事件，每类 6–10 个完整短句/语气变体，采用同一音色、同一响度。按情境和冷却加权抽样，允许不说。缓存只保存通用反应；不预录带任意房号、敌人数或战果的句子，不把单字拼接成僵硬语音。换语言或音色必须重建对应缓存。

例如发现威胁时先有及时的短反应，后续若局势仍成立再补一句具体意图。并非每次都固定“短反应＋解释”，也不能用无关的“嗯、好的”掩盖所有计算等待。CPU 来不及生成的细节，应取消或转成有依据的事后回顾。

调度优先级大致为：生存/死亡/重大变化 → 当前关键行动 → 有时效的观众问题 → 探索评论 → 闲聊素材。同级考虑新鲜度、与当前局面的关联、重复惩罚及观众等待时间，避免持续战斗使观众问题永远饿死。

每次发言前判断“有没有值得说的新内容”。初始调参范围：探索时 5–12 秒的空隙有机会发起一句；等待时 3–8 秒空隙后可接一段话题；战斗以关键事件短句为主，允许几秒安静。它们是机会窗口，不是固定报时器。按最近 60 秒实际播放音频统计占比，探索试 25%–45%、等待试 40%–60%，再用听感调整，不能为了凑比例硬说话。

废除“所有内容共用 90 次生成/小时”作为主要节奏控制，改为实际发声时长、事件冷却、观众公平、模型计算预算分别控制；保留独立资源上限和紧急静音开关。否则提升节奏会在中途耗尽额度并长时间沉默。

5. 及时开口，也要及时闭嘴

输入保留 sourceAt/receivedAt/session/matchId/epoch/eventId；话语保留 intentId/evidenceIds/priority/validUntil/preconditions/interruptible。进队、生成完成、合成完成、开始播放前都校验。换局、手动接管、目标取消要更新代次并淘汰旧任务；一次异步返回不能复活旧台词。

状态类事实按最新观察刷新：紧急反应初始有效期约 1 秒，行动意图约 2–3 秒且目标仍须有效；已确认的死亡/获胜等历史事件可给较长时窗，明确用回顾语气。已生成的旧数字不因状态刷新而自动获得新时间戳。超过时窗就丢弃，不排着队补播过时现场。

只允许“正在播的一条＋下一条候选”，新事件合并或替换候选，长话题以游标保存，别排成语音长龙。紧急事件取消低优先级生成/TTS，并在音频端快速淡出；普通转话题等短分句结束。保护首句最低完整度，避免一点小变化就反复打断。

取消 HTTP 并不等于 Python 已停止推理：需传 jobId/cancel，忽略旧结果，并能在分句之间释放语音 worker。即时缓存使用独立轻量播放路径，不等待正在合成的 worker。不要为每个新事件杀进程重载模型。

先落地分句流水线：Ollama 边生成文本 → 完整短分句做事实/内容检查 → Melo 合成这一句 → OBS 播放；播第一句时准备第二句。不能将半个词直接送 TTS，也不能把 HTTP 分块下载完整 WAV 误称为流式合成。Ollama 原生支持流式返回，现有代码主动关闭了它。

第一阶段可继续用短 WAV 分段，复用现有播放链路；后续只有实测值得时再改 PCM/AudioWorklet 真正流式音频。分段接缝、韵律连续、欠载和取消都需要试听。首句就能独立表达，模型完成第二句之前，不能先播需要后文才能成立的判断。

播放状态与字幕保留时间分离。增加带 utteranceId/segmentId/provider/generation 的 started/ended/interrupted 回执，以播放结束调度下一句；当前回执只有累计计数不足以关联任务。保留超时兜底，某一路 OBS 离线不能阻塞其他路。各平台复用同一游戏解说音频，观众回复继续按平台隔离；某平台落后时跳过旧段，不从头重播。

6. 把决策变成玩家语言

生成输入采用“事实 → 当前意图 → 可核验依据 → 当下情绪 → 最近话题”，输出口语。不要把字段名、调试状态、决策系统术语念出来。自动模式里的意图句应在已经采纳后出现，结果句要等事实确认。

已知情况可说的台词必须满足的依据
选中搜箱目标“这个箱子顺手摸一下，看看有没有能换的。”真实可用箱子、目标已采纳；不知道掉落物
正在搜箱但敌人出现“有人，先不贪这个了。”新敌人可见，实际行为也取消/中断搜箱
已采纳撤离“这儿快不安全了，先换个房间。”危险和撤离计划均有依据；不是只选了备用目的地
低血量并执行掩护“这波先苟一下，血有点顶不住。”血量低且正在执行避险
箱子真的给出好武器“行，刚才没白找，总算能换把主武器了。”可确认拾取/装备变化，且本局之前确实在找武器
路径实际受阻“这边走不通，换条路。”执行器 blocked；不播“需要更多判断”
本局贪搜被打后回顾“刚才想着再摸一个，差点把自己也装箱里。”本局确有该因果顺序；作为自嘲，不编造死因

同一个“搜箱”可以选择好奇、犹豫、简短计划或自嘲等表达，但事实保持一致。同一局内保持稳定性格、称呼和风险偏好；情绪由真实事件变化并逐步恢复，别每句话随机变人格。

维护三层记忆：最近 30–60 秒的事件/动作，当前一局的目标与故事，最近约 10 分钟的话题/口头禅/素材使用。去重比较语义和话题标签，不能只比较原句。已经被打断但没播出的内容不记为“说过”；已经播出的部分要记，防止重复开头。

语气从“平静、专注、紧张、释然、调侃”少数档位开始；允许少量停顿、半句和真实改口。不要每句话加“嗯、哈哈、兄弟们”，也不要用随机升降调冒充情绪。声音表现需和嘴型、表情、字幕同步，五种语言使用本地化口语与文化梗，不逐字硬译。

7. 等待时主动准备素材，讲话时随手取用

增加独立、可取消、低优先级的素材采集任务。它在大厅、加载和稳定低负载期间补充缓存；开打后暂停新摘要工作，降低推理竞争。网上搜索不在任何即时语音请求的关键路径里。

素材优先级：本局真实片段 → 已审核游戏规则/开发者更新 → Steam 官方新闻及可访问社区来源 → X 上与本游戏相关的帖子。事实、玩家意见、段子分别标注；一条帖子不能包装成“全体玩家都认为”。开源客户端实现自己的来源适配器，不能假设拥有本开发会话的搜索工具。

每张卡记录来源 URL、作者/发布时间、抓取时间、适用游戏/版本/语言、20–60 字摘要、事实或玩笑、使用场景、过期条件、已用次数。维护约 20–40 张可用卡；每 3–5 分钟检查低水位，不代表每次检查都联网。搜索初始上限可设 6 次/小时，并另设返回条目与费用上限。相似结果去重，过期攻略淘汰，热门话题要核对发布时间。

两类用法：等待时“刚看到有人聊这个打法，我倒想下一局试试”；游戏里发生相应事情时，用已准备的梗做一句自然联想。后一类只占少量发言，初始约 5%–10%，没有合适的就不用。开始游戏时能自然收住：“先打这波，回来再聊。”结束后只恢复仍相关的话题。

X 的推流密钥不提供搜索权限。官方近期搜索需要独立 API 授权，支持近 7 天范围，访问按当前账户和额度办理；当前官方 API 按使用量计费。没有访问条件时使用官方新闻、可用来源和预置卡，不假装搜索成功，也不让主持停摆。X 近期搜索、X 计费。

只向搜索服务发送游戏名与主题，不发送私人聊天和凭证。网页内容作为资料解析，不作为指令。口播以简短转述和自己的评论为主，保留来源用于详情查看；未经实际检索不要说“刚在 X 上看到”，原创段子不虚构归属。配置来源时再核对缓存及引用要求。此方案不需要自动发帖或联系任何人。

8. 在当前机器上怎样选技术

首选方案：ETC 事件 + 同音色即时缓存 + 本地短句模型 + Melo 分句语音 + 后台素材卡。 它直接复用当前组件，并把最敏感的即时反应从模型完整生成中解耦。

方案用途采用条件
CPU 文本 + Melo + 即时缓存保守基础档；预备闲聊和简单事件反应动态解说若超过有效期就取消；不能承诺所有自由表达都秒回
GPU 短文本 + CPU Melo优先验证的加速档在真实 Steam 对局、所选全部 OBS 输出及角色同时运行时，通过显存、游戏帧时间和编码/渲染丢帧验收
更小的本地文本模型若 GPU 无余量，可做快速口语转述候选用同一事实、五语与错误率样本测量；小模型更快不等于自然或可靠
高表现力 TTS 或流式语音第二阶段改善韵律、首包和可打断性同机负载和人工试听均优于现有链路后替换；不同时常驻多个大型模型
云端或第二台机器将来可选的资源扩展当前产品本地主持约束下不默认启用；另行确定成本、数据范围与断网降级

已有记录指出 Qwen3-TTS 的 CPU/GPU 方案未达到本机直播延迟要求，所以不把“直接换 Qwen”列为第一步。官方确实描述流式能力，但模型能力不等于当前 Python 适配器、Windows 部署与整条 OBS 链路已实现；官方 97ms 也不是本机的端到端承诺。0.6B-CustomVoice 的官方模型表没有 1.7B-CustomVoice 同样的指令控制标记，不能假定现有 0.6B 接口支持完整情绪指令。Qwen3-TTS 官方说明。

Melo 官方描述 CPU 实时推理能力，本机已有短句测量，适合作为第一阶段基础；音色自然度仍需人工评审。MeloTTS 官方说明。

推理调度只保留一个高优先级文本任务，背景素材摘要让路；GPU 档位用持续压力和滞回判断，避免每句话切设备引发重载。GPU 资源不够时先暂停视觉/素材摘要、缩短动态文本，保持游戏与即时反应，不能只看显存空闲就宣布性能足够。

9. 实施节点与交付物

节点具体修改可验收结果

建议新增 host-world.ts、host-events.ts、host-memory.ts、host-materials.ts，复用而非重写 HostDirector、Hosting、模型和音频模块。共享契约放 shared/hosting.ts；观察/表达层不持有游戏输入权限。

10. 验收用“听起来怎样”和可追溯计时

每句话记录：源画面/游戏时间 → 接收 → 事件产生 → 获准发言 → 首个可用分句 → 首段音频就绪 → OBS 实际开始 → 结束/打断。用单调时钟计阶段耗时；跨进程源时间做偏移校验。OCR 要记录截图开始时间，不能只用识别结束时间；实际首声需剔除 WAV 前导静音，播放 started 回执只是近似点。

分别报告采样延迟、排队、模型首句与完整耗时、语音首包/合成、播放等待、源事件到首声，以及观众录像上的“对应画面到对应语音”偏移。平台绝对传输延迟另列，不承诺靠主持架构消除。

验收项初始目标/方法
关键即时反应本机源事件到首个非静音语音 P95 ≤1 秒；记录符合条件事件数、响应数和丢弃原因，防止只挑最快样本
动态行动表达加速档首声 P95 ≤2.5 秒；基础 CPU 档单独报告实际值，超时不能补播过期现场
内容新鲜与准确受控回放中跨局、取消目标、已经死亡仍说正在搜箱等关键错误为 0；模糊描述也人工抽样
说话密度统计实际有声占比和沉默分布；无危险且素材充足时，超过 20 秒的无意沉默需解释，不能用嗯啊刷指标
重复与连续性10 分钟内同一非必要话题/语义复述目标 <10%；至少能准确接续本局一个先前目标或片段
打断与播放紧急事件可及时停下闲聊，无重复首句、无重连补播、无被取消任务复活；多平台回复无串台
自然度原版/改版同素材随机顺序试听：及时、自然、连贯、准确、是否想继续看，各 1–5 分；先由用户试听，再补多位听众；目标自然度中位数 ≥4，无误导性事实
同机性能同画质、同场景、同路数对照；游戏帧时间/1% low 相对基线恶化初始门槛 ≤5%，OBS 渲染和编码丢帧各 <0.1%；双方都达不到时先调整负载，不能只优化语音

先用脱敏的 20–30 分钟事件回放，覆盖探索、激战、等待、观众提问、目标取消、断网、掉线、切模式和换局；再在真实 Steam 安装版 Enter the Cube Playtest 中验证。配对样片比较表达，实时游戏验证资源与延迟，两者不能互相替代。最后在有权限的私密或本机输出做两小时组合测试，五语分别验收发音和梗，不用编辑器演示替代发行版效果。

第一阶段能显著改善的是反应速度、局势一致性、说话密度和连贯性。真人级幽默、细腻情绪与长时间自然互动仍需语料、声音和持续试听迭代；用真实样片决定下一步，不把架构设计当成已经达到真人水平。

A practical plan for a more natural game host

简体中文 · Mobile reading edition

Date: 2026-09-21. Reviewed baseline: 61f60e1. Author: JackZH26 · 𝕏 @jackzhj.

This is a proposal, not an implemented or accepted feature. Evidence comes from source code, selected non-sensitive saved settings, and earlier local measurements. The reported stream has not been timed frame by frame, so its exact delay remains unverified.

Additional delivery in this iteration: chat replay and multilingual spoken replies. That test entry point and language routing are implemented; the broader architecture remains proposed. Hosting defaults to English, supported comment languages receive matching replies, and other languages fall back to English.

1. Recommended experience

Build a host that continuously tracks the situation, chooses worthwhile moments, reacts briefly, expresses adopted intentions, and uses prepared topics during downtime. Reuse ETC/JEV, Ollama, MeloTTS and OBS. Improve information and scheduling before replacing speech models.

Continuity matters: wanting a primary weapon leads to investigating a chest, abandoning it when threatened, acknowledging a successful pickup, and possibly joking about an actual mistake later. Randomness changes expression, never facts or the character's identity.

Prioritize the installed Steam ETC game. In automatic mode, express adopted actions; in manual mode, describe observations or offer suggestions without pretending to control the player. Hosting remains independent of gameplay and broadcasting. Keep the disclosed AI identity.

Saved settings use Qwen3.5-4B on CPU and MeloTTS. Earlier CPU warm full-text requests had a 5.45-second median; a Chinese Melo short sentence took 1.34 seconds. These are separate samples, not one end-to-end trace, but the serial implementation plausibly explains several seconds of delay. The 0.46-second GPU text median was not measured under identical load. See text measurements and speech measurements.

Separate event-to-local-OBS speech delay from platform delivery delay. If both picture and speech arrive late together, transmission is involved; commentary describing an old picture indicates stale content or relative skew. Current responseP95Ms excludes actual playback and the viewer's player.

3. Connect reliable game knowledge

Introduce a read-only HostWorldState from ETC observations, adopted objectives and executor feedback, with source timestamps and session identity. Derive events from changes, not every control heartbeat.

Start with damage, critical health, visible enemies, empty magazine, loot discovery, objective changes, weapon changes, room entry, danger/evacuation thresholds, blocked actions, death and explicit results. Coalesce damage bursts and deduplicate objective lease renewals. Debounce menus, not immediate danger.

Prefer player-visible structured feedback, then valid adopted/executing objectives, timestamped OCR, optional image understanding, and external game material. Guides cannot establish this chest's contents. World coordinates alone cannot justify “enemy on the left” without a reliable camera/screen transform. Hidden information is not a player's observation.

ETC's existing structured interface avoids putting continuous vision inference on the urgent path. Image analysis can run on room changes or unfamiliar objects at low priority; retain capture timestamps and reject late results. Other games need separate OCR/vision acceptance.

Current JEV systemOne asks for action and destination, not a complete spoken rationale. Track proposed → accepted → issued → running → succeeded/blocked/cancelled, with source=jev/local/manual. A rejected cloud suggestion or contingency destination is not an executed plan.

Optional concise reason codes should be grounded in low health, missing equipment, danger or executor feedback. Derive these from evidence without adding a slow reasoning request to control or fabricating JEV's internal reasoning.

Concrete weapon names, counts, results and locations must use allowed fact slots linked to event/material evidence. Reject or rewrite additional unsupported specifics while generating varied speech around those slots. A prompt is not a fact validator: this iteration's replay still produced an unsupported AR-15 claim, making evidence validation an implementation gate.

4. Three content paths, one speaking scheduler

These are software responsibilities, not three resident large models.

PathSourceInitial behavior
Immediate reactionConfirmed event, same-voice pre-synthesized phrase0.4–2 seconds of speech; target event-to-local-first-audio P95 ≤1 second
Intent and situationAdopted objective, current facts and short memory through a local modelOne or two short clauses, usually 2–6 seconds of speech; dynamic first-audio P95 target ≤2.5 seconds, unproven on current CPU
Downtime and interactionMatch history, viewer questions and prefetched material6–15-second passages with pauses; interruptible when play resumes

Start with 8–12 event categories and 6–10 complete phrase/prosody variants each. Match voice and loudness. Use context-aware weighted sampling, cooldowns and the option to remain silent. Do not cache arbitrary room numbers, enemy counts or results, and do not stitch individual words into robotic sentences. Rebuild caches when voice or language changes.

An immediate reaction can precede a generated explanation only while it remains relevant. Do not enforce a fixed reaction-plus-explanation pattern or fill every computation gap with “hmm.” Slow CPU output can be cancelled or turned into an explicitly retrospective comment when supported.

Prioritize survival/death/major changes, important current actions, time-sensitive viewer questions, exploration, then prepared topics. Within priorities use freshness, relevance, novelty and viewer waiting time; prevent chat starvation.

Initial opportunities: exploration after 5–12 seconds of silence; downtime after 3–8 seconds; combat uses selective short reactions and allows concentration. These are opportunities, not periodic mandatory announcements. Tune actual audio occupancy over 60 seconds: exploration roughly 25%–45%, downtime 40%–60%, subject to listening tests.

Replace the shared 90-generation hourly limit as the primary pace controller with separate audio-duration, event cooldown, viewer fairness and inference budgets. Retain resource caps and immediate mute; increasing frequency must not silently exhaust an hourly quota.

5. Start promptly and stop obsolete speech

Inputs carry sourceAt/receivedAt/session/matchId/epoch/eventId. Speech carries intentId/evidenceIds/priority/validUntil/preconditions/interruptible. Validate at admission, generation completion, synthesis completion and playback start. Session changes, manual takeover and cancelled objectives invalidate old jobs.

Initial freshness windows: around one second for immediate reactions; two to three seconds for intent plus a still-valid objective. Confirmed historical death/results may allow longer retrospective windows. New observations cannot silently refresh old generated numbers. Drop expired live commentary.

Allow one playing item and one next candidate. Coalesce or replace candidates; store a topic cursor instead of a speech backlog. Urgent events cancel lower-priority generation/TTS and fade playback quickly; ordinary topic changes wait for a short clause boundary. Avoid interruption churn.

Aborting HTTP does not stop Python inference. Add job identity/cancellation, suppress obsolete results and release the worker between clauses. Cached reactions bypass the synthesis worker. Do not restart the model process for every event.

First implement a clause pipeline: streamed text → complete short clause with factual/content checks → Melo synthesis → OBS playback, preparing the next clause while the first plays. Never feed fragments blindly or describe chunked download of a complete WAV as streaming synthesis. Ollama supports streaming; this application currently disables it.

Use short WAV segments initially; evaluate PCM/AudioWorklet streaming only after measuring benefit. Test seams, prosody, underruns and cancellation. Every first clause should make sense independently.

Separate subtitle lifetime from floor ownership. Playback acknowledgements need utterance, segment, provider and generation IDs, not just counters. Schedule from actual end events with timeouts. One offline output must not block others. Share game-commentary audio across outputs while preserving platform-scoped viewer replies; lagging outputs skip obsolete segments instead of replaying them.

6. Translate intentions into player language

Use facts, adopted intent, verifiable reasons, mood and recent topics. Do not read debugging fields or system terminology aloud. Intent follows adoption; outcome follows confirmation.

EvidenceNatural exampleConstraint
Loot objective adopted“Let's check this chest. Could use an upgrade.”Chest exists; contents unknown
Enemy appears while looting“Someone's here. Chest can wait.”Enemy visible and looting actually interrupted
Evacuation adopted“This room's getting risky. Time to move.”Real danger and current movement plan, not merely a contingency
Low health and cover executing“Need a breather. That health bar isn't looking great.”Both facts confirmed
Primary weapon obtained“Finally, something better. That search paid off.”Pickup/equipment change confirmed and earlier search actually occurred
Blocked route“Can't get through there. Another way.”Executor reports blocked
Greedy looting followed by dangerA short self-deprecating callbackThe match really contained those events; do not invent a cause of death

Keep personality, names and risk attitude stable. Mood follows events and decays naturally. Maintain 30–60-second event memory, a current-match story, and about ten minutes of topic/catchphrase/material usage. Deduplicate semantically. Unplayed cancelled text is not “already said”; actually played partial clauses are.

Begin with calm, focused, tense, relieved and playful styles. Use occasional pauses and genuine corrections without padding every sentence with filler or random pitch shifts. Synchronize voice, mouth movement, expression and captions. Localize all five languages rather than translating jokes literally.

7. Gather material during downtime

Run retrieval as a separate cancellable low-priority task in menus, loading and stable low-load periods. Pause new summarization during combat. Search never blocks immediate speech.

Prioritize actual match moments, reviewed rules/developer updates, official Steam news and accessible community sources, then relevant X posts. Distinguish facts, opinions and jokes. One post does not establish community consensus. The shipped application needs its own source adapters; it cannot depend on this development assistant's search tools.

Each card stores source URL, author/publication time, retrieval time, game/version/language, a short summary, fact/joke label, suitable moments, expiry conditions and usage count. Keep around 20–40 usable cards. Check the low-water mark every 3–5 minutes, without necessarily making a request. An initial limit can be six searches/hour plus independent result-count and spending caps. Deduplicate and expire stale gameplay advice.

Use a prepared topic while waiting, or a small joke when an actual gameplay moment makes it relevant. Start with material-driven jokes at roughly 5%–10% of utterances, never a quota. Interrupt naturally when combat starts and resume only if still relevant.

An X broadcast key does not authorize search. Official recent search needs separate access and covers the past seven days; current API access is usage-priced. Fall back to available official sources and prepared cards if access is unavailable, without pretending a search succeeded. X recent search, X pricing.

Send only game/topic terms to search providers, not private chat or credentials. Treat retrieved pages as data. Prefer brief paraphrases and commentary, retain attribution, and review source-specific caching/quotation requirements during integration. Do not say “I just saw this on X” without a real retrieval; do not attribute original jokes to invented posts. No automatic posting or contacting others is needed.

8. Technology choice on this machine

Recommended baseline: ETC events, same-voice cached reactions, local short text generation, Melo clause synthesis and background material cards.

OptionRoleAcceptance condition

GPU short text + CPU MeloFirst acceleration candidatePass real Steam gameplay, all selected OBS outputs, avatar, frame-time, VRAM and dropped-frame checks

Earlier local CPU/GPU Qwen3-TTS trials did not meet live-stream latency requirements. Its documented streaming capability is not proof that the current Windows adapter and OBS chain stream; advertised 97ms is not a local end-to-end guarantee. The official model table does not mark 0.6B-CustomVoice with the same instruction control as 1.7B-CustomVoice. Official Qwen3-TTS documentation.

Melo documents CPU real-time inference and already has local short-sentence measurements, making it a practical first-stage base; naturalness still needs listening. Official MeloTTS documentation.

Keep one foreground text task, let background summaries yield, and use sustained pressure plus hysteresis for device policy. Avoid switching devices every sentence. Under load, suspend optional vision/retrieval summaries and shorten dynamic speech before harming gameplay. Free VRAM alone is insufficient evidence.

Trace source capture/game time, receipt, event, admission, first usable clause, first audio ready, actual OBS start, end/interruption. Use monotonic clocks for elapsed stages and validate cross-process offsets. OCR needs capture-start timing. Exclude leading audio silence; a playback-start acknowledgement only approximates first audible speech.

The first stage can materially improve responsiveness, freshness, density and continuity. Human-level humor, nuanced emotion and sustained natural conversation require further material, voice and listening work. Judge the next step from real clips, not the architecture alone.

模拟评论与多语言语音回复

已实现的范围

增加独立本地聊天室演练工具，复用正式 Chat → Hosting → Ollama → MeloTTS → OverlayAudio 链路。模拟输入不会调用真实平台连接或发消息。原来的 YouTube/Twitch 连接器保留；本地测试成功不等于真实频道接收、回复和观众端送达已经验收。X 评论连接器仍未实现。

直播默认语言改为英语。回复评论时，以文字中的受支持文字系统判断语言：简中、繁中、日语、韩语使用对应模型输出及 TTS；英语以及支持范围外的语言默认英语。每条回复独立选择，不修改下一条普通解说的语言。混合文字、纯汉字日语及极短消息仍可能存在歧义，当前是低成本规则识别，后续可添加低置信度语言分类；不能宣称任意语言识别准确。

程序默认值不强行覆盖所有人的已保存语言选择；本次用户的“英语默认”应在其当前配置中同步。语音生成按回复语言选自动声音，不沿用不合适的固定异语声音。繁中使用中文语音模型，不代表台湾口音已经验收。

已同步本机保存配置为英语，应用下次加载配置时生效。评论回复使用独立的简短提示，不携带其他观众无关的历史回答；同一观众的相关对话仍可保留。语音前检查输出文字系统，不匹配就跳过并显示错误。初轮试听还暴露过武器术语编造，所以加入了具体游戏信息约束；这些措施仍不能替代内容准确性和自然度的人工评审。

Chat replay and multilingual spoken replies

简体中文 · Natural hosting proposal

Delivered scope

An isolated local rehearsal page reuses production Chat → Hosting → Ollama → MeloTTS → OverlayAudio. Simulation never connects or sends messages to real platforms. Existing YouTube/Twitch connectors remain available; local success does not certify real account reception, reply delivery or viewer playback. X chat is still unsupported.

Default hosting is now English. Each comment independently selects Simplified Chinese, Traditional Chinese, Japanese or Korean when its supported writing system is detected; English and unsupported languages use English. Both model output and TTS follow the choice without changing subsequent ordinary commentary. Mixed scripts, Japanese containing only shared Han characters and very short comments remain ambiguous: this is lightweight rule-based detection, not a universal language classifier.

The schema default does not overwrite every existing user's saved language preference. This user's English preference should also be applied to their saved profile. Cross-language replies use an automatic matching voice instead of retaining an unsuitable fixed voice. Traditional Chinese uses Chinese speech and does not certify a Taiwanese accent.

This machine's saved profile has been changed to English for its next configuration load. Viewer replies use a separate concise prompt without unrelated answers to other viewers; relevant same-viewer conversation can remain. A writing-system check rejects mismatched output before speech and reports an error. Early listening also exposed invented weapon terminology, leading to stricter constraints on specific game claims. These measures do not replace human assessment of factual accuracy and naturalness.

Corpus

The public TwitchChat research archive supplied 2,000 messages from three historical PUBG streams, with 1,734 distinct message texts. Metadata game ID 493057 matches PUBG: BATTLEGROUNDS in Twitch's official reference.

These are historical English chats from 2019, published through Charles Ringer, Mihalis A. Nicolaou and James Alfred Walker's TwitchChat project, whose paper links the dataset. They are not newly captured live comments and do not describe the current ETC match. Direct YouTube replay retrieval encountered a login challenge, so this public source was used instead.

The importer reads only the ZIP directory, metadata and selected members, verifies size/CRC, and avoids downloading video or the entire 324 MB archive. It filters to PUBG, replaces research-hashed viewer identities with local labels, and excludes messages containing links, mentions, emails or likely phone numbers. Existing duplicates remain useful for spam/deduplication tests. Audience text is untrusted, not game telemetry.

Local files: E:\JevRuntime\chat-fixtures\pubg-captured.json and provenance.json, including source member hashes. Corpus files stay outside Git; the code's MIT license does not imply redistribution rights for comments. Additional multilingual acceptance inputs are labelled synthetic, never counted as captured comments.

Final local regression: 187 unit tests, type checks and build passed. Text generation plus synthesis ranged from 5.57 to 12.18 seconds, median 8.08 seconds. These seven functional samples do not establish a latency distribution and exclude full queueing/platform transport.

The pipeline passed; content quality has not passed. Transcript review still found an unsupported AR-15 claim in the first sample and awkward Chinese phrasing. Prompt constraints alone did not establish factual accuracy for the 4B model. Specific weapon/result claims need game-fact allowlists or evidence validation, appropriate knowledge and listening review. Problematic samples are retained rather than presented as human-level hosting.
