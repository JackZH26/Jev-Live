# ETC 专用自动玩：源码分析、实现与验收

[English](ETC_AUTOPLAY.en.md) · 2026-09-20

本阶段只针对 Enter the Cube Playtest（5272970）的人机大逃杀。目标是提高完整对局胜率，逐步接近高水平人类选手；**当前不宣称电竞水平或每局必胜**。自动玩不依赖直播账号、OBS 或开播。正常入口仍是 Steam 游戏库。

## 源码分析结论

分析的是实际 ETC 源码，不是游戏内的 AI 文案。下面的 ETC 路径相对于 ETC 工程根目录；这些游戏源码不复制到 JEV 公共仓库。

| 实现 | 现状与可复用部分 | 对 JEV 的意义 |
| --- | --- | --- |
| `Public/AI/EtcBotController.h`、`Private/AI/EtcBotController.cpp` | AIController + Sight/Damage 感知；视距 3500 cm、丢失视距 4000 cm、半视角 90°；维护 Lyra 装备、背包与队伍组件 | 玩家控制器不能直接变成 BotController，否则玩家输入、相机和生命周期会变 |
| `Private/AI/EtcBotBrainComponent.cpp` | 每 0.25 秒重评；Wander/Loot/Transit/Fight/Evac/Hold；撤离优先、武器排序、弹药检测、拾取、掩体巡逻、路径失败与卡住处理 | 复用规则和设施接口；给本地玩家另建观察/执行层 |
| `Private/AI/EtcBotAimComponent.cpp` | 反应计时、误差锥、开火阈值；直接设定旋转；Pro 请求 ADS | Pro 只是游戏难度名，不能当成电竞水平验收；JEV 应限制转速并测真实射击结果 |
| `Private/AI/EtcBotDifficultySettings.cpp` | Regular 反应 280–420 ms、误差锥 4.5°；Pro 80–120 ms、0.6°、开火门限 0.45° | 可作对照组；不通过降低对手难度制造高胜率 |
| `EtcBotPathfinder`、`EtcRoomStateSubsystem`、`EtcMapAssemblySubsystem` | 房间图、公开坍塌警告、房间内导航与传送门；原 Bot 还能读取计划中的最终安全房 | 玩家策略只读当前公开状态，不输出未来坍塌计划或隐蔽敌人 |
| `EtcRoomHazardSubsystem` 与 015/016/019 专用接口 | 动态危险路径、等待、绕行、蹲/跳、冲刺、脱离危险；部分老房间仍有独立接口 | 在执行层逐帧复用；静态 NavMesh 不能独自处理这些房间 |
| `ULyraQuickBarComponent`、`UEtcConsumableComponent`、`AEtcLootChest` | 装备/弹药、真实治疗读条、背包上限与正常拾取检查 | 调正常玩家接口；不增加生命、弹药、伤害或移动速度 |
| `UEtcMatchResultSubsystem` | 权威击杀数、名次与最终胜者 | 只用官方结算计胜；发出开火命令不等于命中或获胜 |

以上 ETC 源文件主要位于 `Plugins/GameFeatures/EtcCore/Source/EtcCoreRuntime/`；Lyra QuickBar 位于 `Source/LyraGame/Equipment/`。

旧 JEV `electron/game.ts` 由 Windows OCR 提供文字和菜单坐标，250 ms 轮询，默认 800 ms 决策，单次键鼠动作 300 ms。云端从少数单动作中选一个；本地策略是固定动作序列。它没有可靠敌人位置、弹药、危险房间、连续瞄准或正式结算。旧 `EtcJevBridge` 是 200 ms 文件观察、单动作、直接朝目标旋转的原型，且没有接入当时的 Steam 工作台。增加请求频率无法弥补这些缺失。

## 三层控制设计

1. **ETC 原生执行层（每帧）**：观察可见敌人，控制正常玩家，复用武器、治疗、拾取、传送与危险房间规则。限制转速，检查视线和开火条件。游戏线程执行所有游戏操作。
2. **JEV 本地策略（目标 20 Hz）**：选择撤离、找掩体、交战、装填、切枪、治疗、补给和转房间。目标保持、卡住冷却和房间访问记录避免短时来回切换。
3. **可选云端 JEV 战术建议（至少 800 ms 间隔）**：官方 SDK `systemOne` 从当前有效动作中选建议。最多一个请求、1200 ms 超时，不阻塞本地控制。建议权重有限，不能盖过坍塌撤离和低血量约束。换模式后取消请求，旧 epoch/对局/动作的返回丢弃。

`electron/etc-autoplay.ts` 不导入 OBS、OAuth 或 Broadcast。关闭全部直播平台、没有直播凭证仍能使用本地策略。`SteamObserver` 在新路径中只负责识别安装版进程和窗口，不再注入游戏按键。其他 Steam 游戏仍可手动游玩、采集和直播，本阶段没有通用自动玩。

## 本次已实现的控制范围

- 协议 v3 观察自己的生命、弹药、武器、治疗/保护/传送状态、当前房间及公开危险信息；输出当前可见敌人的位置与速度，不输出敌人血量或墙后位置。
- 基于视角、遮挡、闪光、出生保护、传送和队伍伤害关系过滤目标。当前视野近似为前方约 100°、最大 70 m；需要与真实相机 FOV 做后续标定。
- 同时瞄准、射击和有限横移；150 ms 最短持续目标获取时间、360°/s 转速上限、0.8° 开火阈值和小幅稳定误差。这是初始参数，尚未通过人类选手动作分布标定。
- 空弹先切可用武器或装填；低血量且有敌人时找能遮挡已知威胁的掩体；无可见威胁时治疗，保持已有读条。
- 坍塌/预告危险优先向当前安全的相邻房间转移；武器与补给满足基本需求后减少搜箱。当前是局部转房策略，**尚未实现跨多房间的风险最优路径**。
- 导航路径最多每 200 ms 重算；不直穿无有效完整路径的障碍。约 1.8 秒无位移上报卡住，本地策略屏蔽该目标 5 秒。传送和换世界清掉旧路径。
- 复用通用危险房间接口及列车 015、转杆 016、棋盘 019 的原有接口；危险避让优先于开火。**逐房间真实玩家验收尚未完成**，不能据此声称所有危险房间都可稳定通过。
- 使用正常玩家的装备切换、武器 GAS、治疗读条、宝箱和传送入口。初始菜单可开本地 19 Bot 对局；自动重开由已有设置控制。
- 面板显示决策延迟 P95、胜/完整结算数、弹药。仅有 UI/协议连接不算完整对局验收。

尚未实现或验收：按武器特性选择射距/ADS、弹道提前量与下坠补偿、投掷物战术、声音事件记忆、跨房间风险规划、在线对战和长期胜率优化。当前误差与反应参数不能证明“模拟人类选手”已经通过。

## 协议与停止机制

本机私有目录 `%LOCALAPPDATA%/JevLive/etc-bridge` 包含 `session.json`、`state.json`、`command.json`，不进入 Git。集成到游戏版本后，Steam 正常启动即可发现 JEV 会话，不需要普通用户安装源码或填开发工程路径。

- 会话令牌为随机 256 位，1 秒心跳，3 秒会话有效期；会话绑定 SteamObserver 从所选安装目录识别的 PID。编辑器/其他独立测试进程不能领取该会话。
- 观察目标 50 ms 一份，读取上限 128 KB，schema、AppID、PID、session、时钟、递增帧校验。250 ms 以上旧状态不参与操作。
- 指令带 version/session/token/matchId/id/epoch/frame/expiresAt，只能引用本帧附近已经提供的候选动作。无任意控制台、脚本或自定义目标接口。
- 指令租约 250 ms；重复序号、旧 epoch、旧对局、过时观察和超长租约拒绝。租约到期、失焦、断线、换控制器/世界会释放已有自动输入。
- 手动切换提高 epoch、取消云请求，按队列发送释放命令；过时异步结果不能覆盖新的手动状态。Ctrl+Alt+M 仍有效。
- 已发起的新对局允许最多 120 秒等待，直到新世界真正落地；已观察到的穿门过程最多等待 15 秒。期间原生租约照常停止输入，恢复对应的新鲜状态后重新授权控制。
- 普通游戏帧短暂停顿最多等待 1 秒，期间不发送过期动作；仅同一对局/控制代次、仍处于前台的新鲜状态可恢复。超过时限、身份不符或手动接管均停止。Windows 替换状态文件的瞬间缺口仅可复用仍在原 250 ms 有效期内的已验证帧。
- 目前明确限制 `NM_Standalone`。在线模式返回 unsupported，不控制网络对局。

JEV 单实例持有默认 mailbox。并行运行验收时使用 `--isolated`，同时隔离 JEV 数据和游戏控制目录，由 Steam 启动带专用目录参数的安装版游戏，避免替换已有 JEV 的会话。它要求先关闭 Steam 游戏，不修改已有直播实例。普通用户的默认控制通道仍仅支持一个控制器。

## 验收与证据

可复现命令：

```powershell
npm run check
npm test
npm run build
# 仅探测真实 Steam 安装版的接口，不启动自动对局或直播
node scripts/smoke-autoplay.cjs
# 游戏已含接口后，连续完整对局；不配置或启动 OBS
node scripts/smoke-autoplay.cjs --run --matches 20
# 另一套 JEV 正在运行时，先关闭 Steam 游戏，再启动完全独立的单局验收
node scripts/smoke-autoplay.cjs --run --isolated --matches 1
```

ETC 开发者运行 `integrations/etc/install.ps1 -Project <ETC根目录>`，按 ETC 工程的 `Tools/Build.bat` 编译。原生自动化测试为 `Project.ETC.Jev.PlayerMotor`；测试反应时间、最大转速、180° 跨界、帧卡顿、保护/空弹/遮挡禁射和租约/epoch/帧校验。它是代码级测试，不是编辑器对局代替 Steam 验收。

实机脚本报告放 `test-results/etc-autoplay/acceptance.json`，只记录白名单摘要；不导出会话令牌、账号或 API Key。单局结果去重。中途手动介入、退出或缺失结算不能计为自动获胜；中断单列。决策延迟是**观察时间到本机命令写完**，不是端到端命中延迟；弹药减少估计开火数，不冒充命中率。

2026-09-20 新版实测：Steam candidate 安装 BuildID **25420188** 已成功连接 **API v3**，自动开局与实际角色移动已验证。旧版 25364079 的接口缺失结论不再适用于新版。完整对局、输入接管与限制以 [最新验收记录](ETC_AUTOPLAY_ACCEPTANCE.md) 为准。

## 胜率基准与下一次迭代

先在含接口的 Steam 候选版本完成：菜单进入→落地→搜装→交战→跨房间→撤离→官方结算→重开；逐项测失焦、手动接管和拔掉 JEV 后是否停止输入。正式用户路径必须是 Steam 安装/启动的真实版本。

随后做分级对照：同版本、同 Bot 数/难度、记录地图种子，规则策略与“规则+JEV”分组；调参种子与验收种子分离。先至少 20 局功能试跑，再至少 100 局独立验收；同时报告胜率、名次分布、击杀、存活时长、危险房死亡、卡住时间、观察/决策延迟、云建议延迟与输入释放时间。提前退出不能当胜局；失败局必须保留。

建议准入目标（尚未达到）：正常负载下命令延迟 P95 ≤100 ms、断线释放 ≤300 ms（受游戏帧调度影响），19 名 Regular Bot 的 100 局胜率 ≥90%，再提升至 Expert/Pro。只有真实对照数据才能讨论接近电竞水平。有限样本的 100% 胜率也不等于未来每局必胜。

每轮只优化有证据的主要败因：先坍塌/危险房/卡住，再装备经济和射击命中，最后战术。不要用降低敌人难度、修改伤害、透视或跳过失败结算获得漂亮数字。
