# 模拟评论与统一英文播报

## 已实现的范围

增加独立本地聊天室演练工具，复用正式 `Chat → Hosting → Ollama → MeloTTS → OverlayAudio` 链路。模拟输入不会调用真实平台连接或发消息。原来的 YouTube/Twitch 连接器保留；本地测试成功不等于真实频道接收、回复和观众端送达已经验收。X 评论连接器仍未实现。

所有游戏解说和评论回复统一使用英语。评论可以使用简中、繁中、日语、韩语等文字；本地模型用英文回答，Melo 使用原版英文声音播报。音色克隆和按评论语言切换声音的方案已按用户试听反馈暂停。

旧配置加载和保存时统一迁移为英语，旧 Qwen/克隆配置迁移到 Melo。Windows 语音选项仅显示英语声音；旧的异语 Windows 声音不再用于英文播报。界面保留五语。

已同步本机保存配置为英语，应用下次加载配置时生效。评论回复使用独立的简短提示，不携带其他观众无关的历史回答；同一观众的相关对话仍可保留。语音前检查输出文字系统，不匹配就跳过并显示错误。初轮试听还暴露过武器术语编造，所以加入了具体游戏信息约束；这些措施仍不能替代内容准确性和自然度的人工评审。

## 数据来源

已从研究者公开的 **TwitchChat** 数据集中选取 3 场历史 PUBG 直播，得到 2,000 条评论，1,734 条不同文字。来源记录的游戏 ID 是 `493057`，与 [Twitch 官方文档中的 PUBG: BATTLEGROUNDS](https://dev.twitch.tv/docs/api/reference#get-top-games) 对应。

数据是 2019 年历史英语直播聊天，来自 Charles Ringer、Mihalis A. Nicolaou、James Alfred Walker 的 [TwitchChat 研究项目](https://osf.io/39ev7/)；不是今天刚抓到的实时弹幕，不代表本局 ETC 事实。[研究论文](https://cdn.aaai.org/ojs/7439/7439-52-10766-1-2-20200923.pdf)提供了公开数据入口。YouTube 直接回放抓取遇到登录验证后，改用这个公开来源。

采集脚本只读取 ZIP 目录、元数据及需要的成员，不下载视频或整个 324 MB 压缩包；检查解压大小和 CRC。只选择 PUBG 游戏分类，重新编号匿名观众，排除包含链接、账号提及、邮箱和疑似电话号码的记录。数据原有重复保留，用来模拟刷屏与去重；原始内容是非可信观众文字，不作为游戏观察事实。

本机数据位置：`E:\JevRuntime\chat-fixtures\pubg-captured.json`，来源与逐文件 SHA-256 在同目录 `provenance.json`。评论数据不进入 Git，MIT 代码许可不自动扩展到第三方评论。额外中、日、韩及西班牙语验收输入明确标注 synthetic；不冒充抓取数据，也不靠复制合成句子补足“上千条真实数据”。

## 运行

```powershell
npm run build
node scripts/fetch-pubg-chat.mjs E:\JevRuntime\chat-fixtures
node scripts/chat-lab.cjs --dataset=E:\JevRuntime\chat-fixtures\pubg-captured.json --output=test-results\chat-lab-demo
```

最后一个命令输出随机的 `http://127.0.0.1:端口/访问码/` 地址。打开后点击开始，可选择安静、正常、突发和原始时间节奏；正常/突发采用固定随机种子，方便复现。评论统一在回放时获得新的接收时间，历史偏移只决定发送节奏，不让历史日期导致整批消息立即过期。不同源会话按顺序拼接，保留各会话内部时间关系。

依赖已有本机 Ollama 模型 `qwen3.5:4b` 与 `127.0.0.1:11437` 的 Melo 服务；默认 CPU，不读取正式账号。测试输出有明确 SIM 标签；点击暂停只暂停评论，点击全部停止会取消主持和语音。也可以输入一条自己想测试的评论。

网页界面支持五语。两路嵌入的播放器使用正式叠加层，仅演练实例允许当前 loopback 测试页嵌入；正式服务默认仍禁止网页嵌入。回放语音分别在模拟 Twitch/YouTube 侧播放，不跨平台。

```powershell
node scripts/smoke-chat-lab.cjs test-results\chat-lab-demo
```

自动试听检查使用真实本机模型、真实 Melo 合成和真实 Chromium 播放，包含历史评论及英语/简中/繁中/日语/韩语/不支持语言回退样例。输出 `acceptance.json`、实际 WAV、逐条 `events.ndjson` 和手机截图。失败记录独立保存，不把失败运行写成通过。

## 验收口径与后续

2026-09-21 最新更新：语音已切换为全英文，原版 Melo 英文声线；七组实际生成与播放样例通过，包含非英文输入，回复均为英语。新少女与桌面包验证见 [Live2D 与英文播报](LIVE2D.md)。流程通过不代表人工内容或听感验收通过。

早期多语种版本记录（现已停用）：187 项单元测试、类型检查与构建通过。7 条样例全部完成真实本地生成、对应语种合成及 Chromium 开始/结束播放；两路未串台，模型/播放错误计数为 0。文字生成＋语音合成范围 5.57–12.18 秒，中位数 8.08 秒；这 7 条功能样例不是稳定延迟分布，也不包含完整排队或平台传输。

**流程通过，内容质量尚未通过。** 文本复核发现第一条仍凭空提到测试里的 AR-15，另有“拿个掩体”等不自然表达；约束提示仍不足以保证 4B 模型的事实准确。后续必须让命名武器/战果等主张通过游戏事实白名单或证据校验，并完成相关知识接入和真实听感评审。保留这些问题样片，不能把它们包装成已经达到真人主播水平。

本机自包含试听文件：`E:\Jev\test-results\chat-lab-release\chat-listening.html`。其中音频是实际生成结果，随机评论区只回放输入；它不会给每条历史评论伪造新的实时语音。

区分“收到评论、生成回复、合成有声音频、浏览器开始播放、播放结束、真实平台送达”。本地演练只验证前五项，模型或声音的自然程度仍需要人工试听。

现有正式调度仍有等待整句生成、最小字幕/音频保留时间等延迟来源。此次把评论到语音流程做成可运行、可复现的测试入口，并落实语言要求；自然主持方案中的事件抢占、流式短句、素材采集和完整节奏改造并未因此自动完成。

后续切换真实评论时，保留相同的接收/筛选/生成/语音流程，输入使用现有真实连接器。先完成真实频道授权与接收、删除评论、重连、平台隔离，再验证实际播放器中的语音送达。模拟发送路径由独立 Chat 实例限制，即使误把 simulation 标记消息传到 live 实例，也会拒绝发送。
