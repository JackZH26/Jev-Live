## 实测结论

**云端链路有效，当前仍不能评价战斗水平或胜率。** Steam BuildID 25420188，实际返回模型 `jev-1.13.0`。两轮串行探索测试合计 109 次游戏请求、107 次成功回复；另两次由测试结束/控制停止主动取消，没有观测到服务端失败或请求超时。连接检查请求另计。

| --- | ---: | ---: |
| 运行时间 | 181 秒 | 107 秒 |
| 游戏请求 / 成功回复 | 66 / 65 | 43 / 42 |
| 成功请求延迟中位数 / P95 | 358 / 432 ms | 361.5 / 435 ms |

| 完整对局 / 开火 / 击杀 | 0 / 0 / 0 | 0 / 0 / 0 |

第一轮按时限结束，期间有移动和槽位 34 → 1 的变化，后续停在墙边。云端建议虽被接口接收，却没有改变本地策略。第二轮从同一对局的卡住位置开始，补充上下文并采用云端目标后，游戏回报了目标变化，但 106 次游玩位置采样完全相同；画面对应房间 005、运行时槽位 1，未脱困。原生端随后退回 manual，控制器检测为 `etc.lost` 并停止；现有原生状态未提供更细的停止原因，不能断言具体是哪项保护触发。

因此不能把“107 次成功回复”解释为“107 次有效游戏操作”，也不能把第二轮当成整局自动玩。需要优先修复游戏导航/脱困、卡住诊断及原生停止原因，再做固定条件的规则/云端对照与多局胜率测试。默认提示下反复扫描、增加动作语义后选择探索目标，说明提示与采用方式影响很大；并不足以证明模型理解完整游戏。

本地原始证据：`test-results/cloud-jev-1789912278224/acceptance.json`、`test-results/cloud-jev-1789912474709/acceptance.json`。成功游戏请求合计 189,383 输入 token、15,954 输出 token；不包含连接检查或被取消请求的未知服务端用量，不推算账单金额。准备阶段的过期进程探测和已修复的测试统计递归错误均不计入这两轮有效实测。

## 可复现脚本

使用已有的 Windows 加密 Jev 凭证；脚本不会要求在命令行传入明文 Key，也不会复制账号库。优先尝试桌面加密存储，再使用此 Windows 用户已有的 JevBrowserOperator DPAPI 凭证。没有凭证时停止。解密值仅留在私有子进程管道和进程内存中。

```powershell
npm run build
npm run build:native
# 仅验证云端连接；不会控制游戏
npx electron scripts/validate-jev-cloud.cjs
# 必须没有运行中的游戏，由 Steam 启动独立控制目录
npx electron scripts/validate-jev-cloud.cjs --run --launch --seconds 180
# 隔离实验：补充目标含义和近期玩家观察，让云端决定非紧急探索目标
npx electron scripts/validate-jev-cloud.cjs --run --launch --seconds 180 --tactical-experiment
```

两种运行命令应分开执行；每次 `--launch` 都要求 Steam 游戏已关闭。脚本不会关闭已有游戏。也可用 `--bridge <隔离目录> --pid <已核对的Steam进程>` 接管已经闲置、原控制租约过期至少五秒的测试实例。目录必须位于当前用户 LocalAppData 的 `JevAutoplayAcceptance-*` 或 `JevCloudAcceptance-*` 下，不能接管正式默认控制目录。

`--runtime <dist-main目录>` 可选择已构建的只读代码快照，避免另一个开发会话改动正在验证的代码；报告记录控制器、桥接和策略文件 SHA-256。时长限定 10–600 秒，游戏请求最多 120 次，每轮先有 3 次独立连接检查。结束后请求手动模式并核对原生输入释放。退出码 0 表示连接检查完成或有正式对局结算，1 表示错误，2 表示有界实测结束但未完成对局。

## 两种策略的边界

默认策略保持产品行为：云端只对其建议动作增加少量分数。实验策略同时增加了动作含义、最近 12 次玩家观察，以及至多三秒的战术目标保持时间。每帧仍重新检查动作是否可用、安全、未列入失败目标；原有前台、身份、250 ms 新鲜度和输入租约不变。危险撤离、低血量、可见敌人、治疗、换装、换弹和掩护仍由本地规则优先处理。

这是**结构化战术选择**实验，不是让模型直接接管键鼠或渲染帧。实验只存在于测试脚本，未改动正式自动玩默认行为，也未修改游戏二进制。它同时改变上下文和建议采用方式，不能用作模型胜率或纯粹的 A/B 性能比较。

`adviceSelected`、`changedFromRules`、`changedAndObserved` 是采样/控制帧计数，不是独立云端回答或完成动作数量。最后一项只证明游戏 `lastAction` 回报了相应目标；坐标、弹药、击杀和正式结算才反映进一步的游戏效果。原始报告位于被 Git 忽略的 `test-results/cloud-jev-*/acceptance.json`。

接口用法参照 [TypeSafe 官方 JavaScript SDK](https://docs.typesafe.ai/sdk/javascript)。返回的模型置信度不等于游戏胜率。
